# QA and stress-test report — RFQ-to-quote n8n workflow (demo)

**Date:** 2026-10-11 · **System under test:** `workflow.e2e-webhook.json` on a self-hosted n8n instance
**Data:** synthetic catalogue and RFQ only. Run labels A–E refer to the five live executions; internal IDs are kept privately. This is a demonstration of method, not client delivery.

## What was tested and how

| Layer | Method | Result |
|---|---|---|
| Matching and money logic | 33 unit checks (`quote.test.js`), incl. half-up rounding edge cases | 33/33 executed and passed |
| Live workflow, happy path | Real text PDF uploaded over HTTPS to the live webhook; returned .xlsx unzipped and every line compared with the locally tested logic | PASS — 14/14 lines identical, total 1281.10, 0 differences (run B, ~5 s) |
| Failure handling | Non-PDF file, empty file, missing file | PASS after fix — each returns HTTP 422 `FAILED` with its run ID (runs C, D, E) |

## Defects found (and fixed before the passing run)

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| D1 | High | Line totals rounded with floating point: 0.145 × 1 became **0.14** instead of 0.15 (half-up) | unit check written for the case | All money math moved to exact integer micro-units; checks for 0.145, 0.125 and 0.005 × 3 |
| D2 | High | First live run failed: n8n stores multipart uploads as `rfq_pdf0`, the extract step looked for `rfq_pdf` | run A, error "no binary field 'rfq_pdf'" | Field name corrected; caught only by a live run — static validation had passed |
| D3 | High (fail-open) | When the run failed, the caller still received **HTTP 200 with an empty body** — a client could treat it as success or reuse an old file | run A + HTTP response | Error outputs of the extract and matching steps now route to an explicit 422 response carrying run ID and "no quotation produced" |

## Controls that hold (verified)
- Prices only from the approved list; description matches, substitutions and missing prices are **never priced** and appear in a "Needs review" section.
- Every output carries run ID, timestamp, currency and price-list version, so a stale file cannot pass as a fresh result.

## Not tested yet (stated plainly)
- Scanned/image PDFs (needs OCR), multi-page RFQs, very large catalogues, concurrent uploads, the form-trigger variant end-to-end, non-English headings, real customer layouts.

## Method, reusable for any n8n / AI-agent workflow
1. Test the logic in isolation with edge cases chosen to break it (rounding, units, ambiguity).
2. Run the real workflow end-to-end on the real platform with a real file; compare outputs field by field with the tested logic.
3. Inject failures (bad, empty, missing input) and check what the *caller* sees, not just what the logs say.
4. Report every defect with its execution ID, and what remains untested.
